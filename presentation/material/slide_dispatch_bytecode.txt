── OPERANDENZUGRIFF (blue) ───────────────────────────────────
 Pop inputs from the operand stack, push result
 Each invokevirtual = virtual dispatch + ArrayDeque bounds check + heap deref

   179: aload_3                         // load OperandStack reference
   180: invokevirtual popI32()          // pop b   ← ArrayDeque.pop() + .asI32()
   183: istore        7                 // store b in JVM local slot 7
   185: aload_3                         // load OperandStack reference
   186: invokevirtual popI32()          // pop a   ← ArrayDeque.pop() + .asI32()
   189: istore        8                 // store a in JVM local slot 8
   191: aload_3                         // load OperandStack reference (for push)
   192: iload         8                 // load a
   194: iload         7                 // load b

── NUTZLAST (green) ──────────────────────────────────────────
 The actual semantic work of i32.add

 COMPARISON with C switch-based interpreter (slide 18):
   Dispatch:           both use O(1) table jump                ✓ same
   Operandenzugriff:   C does sp[1]+=sp[0]; sp++  (~3 insns)
                       Java does 3× invokevirtual              ✗ much more
   Nutzlast:           C: addl; Java: iadd                     ✓ same
