 SLIDE: JVM C1 JIT — What execute() Compiles To

The JVM (C1 compiler tier) inlines and compiles execute() after ~10k calls.
The annotation comments confirm the sequence inside the compiled native code:

  ── DISPATCH ──────────────────────────────────────────────────
  ; stats.dispatches++ (line 45)

  ; getfield operandStack (line 46)
  ;   loading the OperandStack object from the Frame

  ; invokedynamic typeSwitch (line 48)
  ;   Interpreter$$TypeSwitch — maps sealed subtype to int index
  ;   (similar to C's switch label; O(1) via tableswitch)

  ; tableswitch (line 48)
  ;   25 cases: ConstI32=0, I32Add=1, ..., Unreachable=24

  ── OPERANDENZUGRIFF ──────────────────────────────────────────
  ; {metadata for OperandStack::popI32 '()I'}
  ; - com.group1.interwasm.util.OperandStack::popI32@1 (line 41)
  ; - com.group1.interwasm.runtime.Interpreter::execute@958 (line 140)
  ;   ↑ JIT INLINED popI32 into execute() — but still:
  ;     invokevirtual Deque::pop() = virtual dispatch + ArrayDeque bounds check

  ; {metadata for OperandStack::pushI32 '(I)V'}
  ; - com.group1.interwasm.util.OperandStack::pushI32@... (line 36)
  ; - com.group1.interwasm.runtime.Interpreter::execute@... (line ...)
  ;   ↑ JIT INLINED pushI32 into execute() — same story

  ── NUTZLAST ──────────────────────────────────────────────────
  ; iadd — one native ADD instruction
  ; The JIT does NOT lift this to a register op because the inputs
  ; must first be extracted from the ArrayDeque heap objects.

──────────────────────────────────────────────────────────────
 Key insight from JIT output:
──────────────────────────────────────────────────────────────

  ✓ Dispatch: typeSwitch+tableswitch compiled to O(1) jump table (good — same as C)
  ✓ Nutzlast: iadd/isub/etc compiled to single native instruction (good — same as C)
  ✗ Operandenzugriff: each pop/push still goes through ArrayDeque.pop()/push()
      → virtual dispatch (invokevirtual, even if JIT inlines it)
      → object allocation: every WasmValue is a heap-allocated record
      → GC pressure from short-lived WasmValue objects on every arithmetic op
      This is the main cost that a C interpreter avoids with a plain int sp[] array.
